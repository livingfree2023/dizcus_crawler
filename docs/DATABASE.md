# 抓取历史与首次存档

## 存储位置及身份

- 使用 Python 标准库支持的 SQLite，存放于 `data/archive.sqlite3`，与 `output/` 中的 HTML 分开管理。
- 归档身份为配置指定的稳定 `forum_key` 加帖子 `tid`，建立联合唯一约束。同一帖跨板块出现或列表参数变化不影响身份；同一论坛更换镜像域名时沿用 forum_key。
- 成功记录包含 forum_key、tid、首次归档标题、相对文件路径、UTC 归档时间、文件字节数和 SHA-256。正文与图片只存于 HTML，不复制到数据库。
- schema v2 新增 `rejected`，保存 forum_key、tid、available_images、min_images、reason、rejected_at；不保存被跳过帖子的正文或图片。v1 在下次抓取持锁后事务升级，原成功记录、待完成记录和身份原样保留。
- 标题不能充当唯一键；同名帖子可能不同，已归档帖标题也可能在源站变更。

## 不可更新规则

1. 扫描精华列表后先查询成功和永久跳过历史。任一命中立即跳过，不请求正文和媒体，也不再次核验该帖的精华置顶标记。
2. `min_images > 0` 时成功图片足量才保存正文与成功图片；不足则写入 rejected 终态，没有 HTML 或 pending。`min_images = 0` 或未配置时沿用旧版全部目标图片完整后才保存、失败允许重试。
3. 已成功记录是终态，常规运行不能改写、重命名、覆盖或主动刷新。源站后续编辑或删除都不影响本地副本。
4. 成功记录对应HTML被移走或删除是正常使用场景。抓取不检查该文件是否存在，不计failed，不重抓；--check只报告missing_files信息并允许正常退出。仍在本地的文件若摘要不符或路径不安全，检查仍报告错误。
5. 卸载服务、更新程序均保留数据库和 HTML；备份与迁移须成对保留。删除数据库会丢失去重依据，不能自动当作安全重建。
6. `rejected` 和成功归档一样不可更新或删除。调低阈值、更换 Cookie、图片恢复或源帖编辑都不解除永久跳过；既有成功存档不按新阈值回溯。
7. 数据库触发器保证同一 forum_key+tid 不能同时出现在 rejected 与 archives/pending，避免已排除的帖子意外存档或已有完整快照被改判排除。

## 文件与数据库一致性

SQLite 与文件系统不能构成同一个原子事务。`pending` 表持久化待提交记录，包含预定路径、临时文件名与已验证文件的摘要；文件完成写入并 fsync 后，使用同目录硬链接发布，禁止覆盖已有文件，再在同一数据库事务里插入成功历史并删除 pending。

崩溃恢复先核对待提交记录与本地最终文件，匹配后直接补记成功，不能因成功记录尚未落库就重新抓取。如果只留下未完成临时文件，则属于失败尝试，可清理并重试。用进程锁和数据库唯一约束共同防止手动任务与定时任务争抢。

输出目录 `.discuz-archive.json` 与 SQLite `meta.identity` 绑定，防止历史丢失后自动重新初始化；marker 与历史同样需要备份。仅有 rejected 没有 HTML 时也受身份保护。成功表与 rejected 的 UPDATE/DELETE 均由触发器拒绝。`pending` 文件若已准备好却丢失或损坏，拒绝自动重新下载以保护首次接受归档的版本。

marker内容是随机identity和格式version，不含帖子列表、下载进度、Cookie或Web密码；用户只需移动已完成的HTML。删除或移动marker与移动HTML不同，仍属于身份保护失败。Web访问已移走的HTML返回404，不终止服务；先打开文件再发送响应，避免并发移走导致重复发送错误响应。

备份前停止抓取与阅读服务，复制完整工作目录中的输出和状态；不要在任务仍写入时仅复制一个 SQLite 主文件。恢复时保留相对目录布局与输出 marker。

## Web 读路径

列表仅查询成功记录并分页；阅读仅加载记录指定的本地文件。读取与诊断均不访问源论坛。SQLite 和运行状态目录不通过静态服务公开。

实时进度 `progress.json` 是独立的运行观测数据，不承担永久去重；损坏或丢失不影响 archives/rejected/pending。安装时对该具名状态文件的 root 所有权迁移与数据库一致处理，不递归接管其它账号的数据。

`--check` 和 `/api/debug/state` 返回 rejected 计数，但不将业务筛选当成本地完整性错误；旧 v1 历史在尚未触发写入迁移时也可只读查看（rejected 为 0）。
