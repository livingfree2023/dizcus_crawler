# 抓取历史与首次存档

## 存储位置及身份

- 使用 Python 标准库支持的 SQLite，存放于 `data/archive.sqlite3`，与 `output/` 中的 HTML 分开管理。
- 归档身份为配置指定的稳定 `forum_key` 加帖子 `tid`，建立联合唯一约束。同一帖跨板块出现或列表参数变化不影响身份；同一论坛更换镜像域名时沿用 forum_key。
- 成功记录包含 forum_key、tid、首次归档标题、相对文件路径、UTC 归档时间、文件字节数和 SHA-256。正文与图片只存于 HTML，不复制到数据库。
- 标题不能充当唯一键；同名帖子可能不同，已归档帖标题也可能在源站变更。

## 不可更新规则

1. 扫描精华列表后先查询成功历史。已有成功记录，立即跳过，不请求帖子正文和媒体，不进行编辑时间或内容哈希的远程检查。
2. 只有正文、全部目标图片、GIF 和最终 HTML 都保存成功，才成为成功归档。失败或未完成记录允许重试，不能提前当作完成。
3. 已成功记录是终态，常规运行不能改写、重命名、覆盖或主动刷新。源站后续编辑或删除都不影响本地副本。
4. 成功记录对应文件丢失、被改动或损坏时，仅报告本地异常，不重新下载当前版本。恢复应从备份找回首次副本。
5. 卸载服务、更新程序均保留数据库和 HTML；备份与迁移须成对保留。删除数据库会丢失去重依据，不能自动当作安全重建。

## 文件与数据库一致性

SQLite 与文件系统不能构成同一个原子事务。`pending` 表持久化待提交记录，包含预定路径、临时文件名与已验证文件的摘要；文件完成写入并 fsync 后，使用同目录硬链接发布，禁止覆盖已有文件，再在同一数据库事务里插入成功历史并删除 pending。

崩溃恢复先核对待提交记录与本地最终文件，匹配后直接补记成功，不能因成功记录尚未落库就重新抓取。如果只留下未完成临时文件，则属于失败尝试，可清理并重试。用进程锁和数据库唯一约束共同防止手动任务与定时任务争抢。

输出目录 `.discuz-archive.json` 与 SQLite `meta.identity` 绑定，防止历史丢失后自动重新初始化；marker 与历史同样需要备份。成功表的 UPDATE/DELETE 均由触发器拒绝。`pending` 文件若已准备好却丢失或损坏，拒绝自动重新下载以保护首次完整版本。

备份前停止抓取与阅读服务，复制完整工作目录中的输出和状态；不要在任务仍写入时仅复制一个 SQLite 主文件。恢复时保留相对目录布局与输出 marker。
