# 正文图片阈值与永久跳过

## 用户确认

- 配置可设正文中成功获取图片数量的最低阈值；不足时不生成存档，未来也不再抓取该帖。
- 用户明确确认：达到阈值时，保存正文和成功获取的图片；同帖中失效或无权限的图片舍弃。
- 成功归档与永久跳过都是终态。调整阈值、链接修复或补充权限不重置历史。

## 配置与计数

- 新增 `[archive] min_images`，非负整数。代码缺省 0 保持旧配置行为；示例配置推荐 1。
- 0 关闭阈值功能，继续旧版“所有目标图片完整才成功、失败可重试”的契约。
- 大于 0 时逐一尝试净化后的主楼图片与图片附件，统计成功下载并通过格式校验的不同图片源；相同原始 URL 不重复计数，多帧 GIF 算一张。
- 回复、签名、头像、广告、占位图、追踪图不计入正文图片数量。
- 单张图片的网络/HTTP/格式错误视为不可获取，继续检查其余图片；满足阈值时不将坏链接留在 HTML。
- 完成检查后若成功数量低于阈值，抛出携带计数的业务终态，由爬虫记录永久跳过，不写 HTML 或 pending 文件。
- 已确认的正文/附件权限页及帖子 HTTP 401/403/404/410 可判定无可获取正文图片（0）；无法识别的模板或整页临时网络/5xx错误不伪造计数，保留错误重试。

## 历史与迁移

- SQLite schema 从 v1 升级到 v2。新增 `rejected`，主键为 forum_key + tid，保存 available_images、min_images、reason、rejected_at，只有必要元数据，没有正文或图片。
- 迁移在事务中完成，保留既有 archives、pending、identity 与不可变约束。未知版本拒绝写入。
- `archives` 和 `rejected` 都是不可更新/删除的终态；与 pending 之间增加防冲突约束。
- 扫描列表后先查两类历史，再决定请求正文或核验精华置顶；永久跳过的帖子不再次请求正文/媒体，不在 Web 存档列表展示。
- 输出身份保护同样覆盖仅有 rejected 的库，防止历史丢失后重新初始化导致重复抓取。
- 当次新增永久跳过计入 rejected，不视为运行失败；下次命中计入 skipped。原始故障仍计入 failed。
- 本地检查及只读诊断返回 rejected 数量，旧 v1 历史在抓取迁移前也能只读查看。

## 验证计划

- 单元：阈值类型/边界、GIF/重复源计数、坏图过滤、权限块清理。
- 模块：v1 迁移保留旧记录和待完成存档，跨终态互斥、不可变触发器、跳过后调低阈值/补 Cookie 仍保持终态、历史身份保护。
- 集成：真实 localhost HTTP + 临时 SQLite + CLI 验证不足无文件、满足仅保存成功图片、失效图片/权限/登录页、后续零正文/媒体请求、Web 仅展示成功帖。沿用明确标注的中性素材，不对原站点做测试。
- 无 UI 变更，不需新增视觉原型；单一生产脚本约束保持。
