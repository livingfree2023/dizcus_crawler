# Discuz 精华帖离线存档

## 当前范围

用户已授权完整开发与 Git 初始化。生产实现为单一 Python 标准库脚本，Web 为精简存档列表与点击阅读，不做板块分类或任务管理面板。原型和测试使用中性素材，不包含用户提供站点的真实帖文或媒体。

## 目标契约

- 从配置读取论坛首页、可选 Cookie 文件、板块选择、超时、请求间隔、输出目录和每日运行时间。
- 发现板块，遍历精华筛选列表和分页，以配置中的稳定论坛身份 forum_key 及 tid 去重。不能仅凭标题含“精华”判定；相同论坛更换域名不应生成新的身份。stock Discuz 精华筛选会隐藏图标，因此使用服务器渲染的活动精华标签或 listextra 证据确认筛选；无确认时仅接受明确的精华图标，不凭请求 URL 猜测。
- 无图标置顶需用同板块普通列表的精华图标另行核验，每板块最多一次；未能核验则不归档，报告扫描未完整，不能把注入的非精华置顶当成精华。
- 只提取主题第一页的第一楼正文；不包含楼主后续回复、其他回复、签名、头像、等级、点赞、收藏、分享、评分及广告。
- 最终输出 `output/<首次成功存档时的标题>.html`。非法文件名安全替换，同名不同帖追加 tid。首次完整存档成功后永久跳过；后续标题、正文、图片变化都不请求、不更新，也不重命名。
- 历史记录独立存储于 `data/archive.sqlite3`，具体持久化契约以 `docs/DATABASE.md` 为准。扫描列表后先查历史，再决定是否请求正文和媒体。
- 图片以原始字节嵌入 data URI，保留 GIF 动画；不能仅改扩展名或转换成静态图片。
- 归档不含远程资源、脚本、iframe、事件处理器、追踪像素及论坛交互控件。正文链接保留前需验证协议。
- 下载失败、权限限制、内容缺失不能当成成功，未完成的帖子下次可重试。通过临时文件、持久化待完成记录与原子提交保护最终文件；禁止覆盖已成功归档的文件，崩溃恢复优先核对本地文件。
- 默认克制串行请求，限速并尊重服务限制；登录与访问控制不绕过。

## 调研现状与边界

- 仓库初始为空。
- 已通过网络工具访问用户提供的首页。首页显示该站主要包含露骨色情内容；没有继续提取该站帖子或下载媒体。
- 网络工具无法访问用户提供的精华列表与帖子链接，未验证这些页面的 DOM、权限、分页、图片加载及防盗链行为。
- 标准模板已依据官方源码、普通数码论坛精华列表及本地 HTTP 集成测试实现；未验证用户提供站点的定制模板。外部图片链路因普通论坛附件权限限制未完成，不把本地测试视作线上成功。

## 本地原型

`docs/prototype/output/离线存档示例.html` 是独立文件：包含示例标题、作者、时间、正文、内嵌 SVG 图片与真正的多帧 GIF。SVG 仅为中性原型插画，生产阶段对不可信 SVG 采用安全处理策略，不直接内嵌可执行内容。

单帖原型没有外部资源和 JavaScript，不依赖 Service Worker。单文件本身可直接离线打开。列表原型为 `docs/prototype/index.html`，截图为 `docs/prototype/preview.jpg`。实际 Web 列表与点击阅读已在回环 HTTP 服务中通过浏览器检查；Manifest 与中性离线页缓存均由脚本提供，缓存不承担抓取历史或去重职责。

## 实现

数据流：配置 → 会话 → 板块发现 → 精华分页 → 查询历史并跳过成功项 → 首楼抽取 → 净化 → 媒体下载/验证 → 原子保存与历史提交。

采用 Python 3.11+ CLI 与可选只读 Web 阅读服务，无第三方依赖；HTTP 使用 urllib，DOM 使用 HTMLParser，历史使用 SQLite。提供本地只读诊断命令与结构化运行日志，记录帖子标识、阶段、耗时、失败原因；不记录 Cookie 或带凭据的完整 URL。

### 精简 Web 阅读界面

- 首页只列出已成功归档的帖子，标题为主要内容，可显示首次归档日期；按归档时间倒序排列，不分板块。数量大时分页。
- 点击标题直接阅读本地 HTML；正文及媒体仅从本地读取，页面访问不触发抓取、补图或更新。
- 列表查询 SQLite，内容路由使用归档记录 ID 映射受限目录内的文件；不开放任意路径读取或整个状态目录。
- 不提供论坛配置、手动抓取、编辑、删除、任务日志等管理界面。
- 默认绑定回环地址，远程访问须鉴权。只读诊断接口仅返回脱敏计数与状态，限制访问频率，不返回 Cookie、正文或敏感路径。
- 抓取任务由 CLI/systemd 独立执行，Web 阅读服务按需常驻；安装时明确区分阅读服务与抓取 timer。

### systemd 生命周期

- `--install`：为 Debian/Ubuntu 创建 oneshot service 与每日 timer，使用绝对解释器、配置和工作目录；独立低权限账号运行，敏感配置限制权限。
- 使用 `OnCalendar` 并明确时区；`Persistent=true` 补跑关机期间错过的任务。每日默认时间拟为服务器本地时间 03:00，可配置。
- 避免手动执行与定时执行并发写入，使用进程锁。
- `--uninstall`：停用 timer，停止在途抓取及已安装的阅读 service，删除本工具拥有的 unit 文件，执行 daemon-reload；重复卸载应安全，保留配置、日志、SQLite 历史及存档。
- 安装或卸载系统 unit 需要管理员权限；普通抓取不需要 root。

## 三层验证计划

- 单元：文件名与同名处理、URL 安全、分页去重、净化规则、图片类型校验、GIF 字节保持、原子写入失败恢复、稳定论坛身份以及路径约束。
- 模块：明确标注的离线 HTML fixtures 验证仅第一楼、懒加载图片、广告控件清除、缺图失败状态、历史索引及 unit 生成/归属识别。已归档帖子改标题/正文/图片后再次运行必须不请求正文或媒体、不修改文件；文件丢失也不自动重新抓取。验证提交中断恢复及唯一键冲突。验证 Web 列表仅列出成功项、分页、点击阅读及无外部请求。fixtures 不进入生产数据。
- 集成：对授权且不含露骨内容的真实站点验证会话、板块及精华分页、图片 Referer、完整归档以及第二轮运行跳过成功项；在真实 Debian/Ubuntu systemd 环境验证安装、触发、重复安装、卸载与重复卸载，确认历史与归档保留。没有环境时明确记录未验证。
