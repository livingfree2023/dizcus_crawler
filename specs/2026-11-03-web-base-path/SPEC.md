# Web子路径反代

## 真实诊断

目标Caddy只精确匹配 /dizcus_crawler 并原样反代；后端只认识 /，所以认证通过后404。后端首页和debug直连均200。Caddy path默认精确匹配已由官方文档确认，仅strip首页不足以修复绝对链接。

## 契约

- [web] base_path，默认空保持根目录部署。非空必须为绝对路径的安全命名段，去掉尾斜杠；拒绝URL、查询、片段、百分号、点段、重复斜杠和非字符串。
- 后端接受带前缀路径并内部去除，裸路由保留本机健康检查兼容。前缀本身308到尾斜杠，保留查询，可在认证前执行无内容跳转。
- 标题链接、分页、静态资源、manifest的start_url/scope/icon、app.js注册和Service Worker缓存/Scope均携带前缀。不同前缀缓存相互隔离，不能删除同源其它实例缓存。
- Basic密码规则保持，所有内容请求依然鉴权。单文件存档字节保持原样。
- Caddy匹配精确入口及prefix/*两个路径，使用handle原样转发；不干预其它应用。
- 远程变更前保留权限受限的配置备份，validate通过才替换并reload；只restart阅读服务，不启动抓取验证。真实HTTPS请求在本机使用正确SNI和证书校验，密码仅内存使用。

验证：纯函数配置与URL边界、本地真实HTTP认证/分页/文章/下载/PWA路径、完整回归；目标Caddy配置校验与HTTPS首页/资源/diagnostic只读检查。不展示或抓取真实帖文做验证。
